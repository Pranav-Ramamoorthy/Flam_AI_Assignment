### 1. Executive Recommendation: Path (c) — Prompt Engineering
We recommend **Path (c): Prompt-Engineering Only** as our primary launch vehicle, rejecting Path (b) (Rewriter Model) and deferring Path (a) (SFT). Under the hard 3-week timeline and zero external API budget, prompt engineering is the **only path that is verifiable, operationally viable, and safe from unmonitored multilingual degradation**.

---

### 2. Explicit Assumptions
1. **Reviewer Capacity**: 1 reviewer (fluent in Hindi & Kannada only) working 10 h/week for 3 weeks = **30 total review hours**.
2. **Review Speed**: A thorough evaluation of a prompt-response pair (checking casual tone, grammar, and factual fidelity) takes **2.5 minutes per pair**, yielding an absolute maximum budget of **240 evaluations/week** (720 total evaluations across 3 weeks).
3. **Multilingual Blind Spot**: We have **zero internal validation capability** for Tamil, Telugu, Bengali, and Marathi. Any weight modification (SFT) risks catastrophic language degradation or safety failures in these four unmonitored languages.
4. **Synthetic Data Constraint**: With $0 external API budget, synthetic data for Path (a) or (b) must be generated by our base model (FLM-4B). If FLM-4B cannot produce casual outputs via prompting, its synthetic training pairs will be low quality, formal, or ungrammatical.

---

### 3. Back-of-Envelope Arithmetic

| Parameter / Dimension | Path (a): SFT Pass | Path (b): $\le$1B Rewriter | Path (c): Prompt-Engineering |
| :--- | :--- | :--- | :--- |
| **Data Requirements** | $\ge$5,000 vetted pairs/lang (30,000 total) | $\ge$15,000 pairs across 6 langs | **3–5 few-shot exemplars per language** |
| **Reviewer Coverage** | 720 / 30,000 = **2.4% audited** (unsafe) | 720 / 15,000 = **4.8% audited** (unsafe) | **720 / 720 = 100% of test suite audited** |
| **Compute / Hardware** | 1× A100 for 10–14 days (training + eval) | 1× A100 for 12 days (train 1B model) | **0 training hours** (1× A100 used for eval) |
| **Serving Overhead** | 0 ms latency, 0 GB extra VRAM | **+150–300 ms TTFT/ITL**, +2 GB VRAM | **+120 prompt tokens** (~1.2 ms TTFT prefill) |
| **Failure Risk** | Knowledge forgetting & safety drift in 4 langs | Hallucination / dropping user entities | Easily reverted via config flag |

- **Serving Latency & Memory**: Path (b) requires a second autoregressive decode step, cutting server throughput by ~40% and consuming ~2 GB VRAM. Path (c) adds ~120 tokens of system prompt context: at 170,000 tok/s prefill on L4, this adds only **~0.7 ms to TTFT** and negligible KV memory.
- **Reviewer Throughput Allocation**: Split 240 pairs/week into 120 Hindi and 120 Kannada pairs. Over 3 weeks, this yields 360 audited pairs per language—statistically sufficient for a rigorous confidence interval ($\pm 5\%$).

---

### 4. Success Metric with Numeric Threshold
$$\boxed{\mathbf{S} = \text{Pairwise Blind Win-Rate} \ge \mathbf{75\%} \quad \text{AND} \quad \text{Factual Hallucination Rate} \le \mathbf{2.0\%}}$$
Evaluated via blind A/B testing by our native reviewer on 200 held-out conversational scenarios (100 Hindi, 100 Kannada) comparing casualized responses against current formal baseline outputs. Responses must score $\ge 4/5$ on native colloquial naturalness while preserving 100% of core facts and safety constraints.

---

### 5. Kill Criterion & Milestones
- **Milestone 1 (Day 7)**: Evaluate initial prompt templates on 100 Hindi and 100 Kannada prompts.
- **Kill Criterion**: If the blind casual win-rate on Day 7 is **$< 65\%$** or if the prompt causes **$> 3\%$ safety/instruction-following regressions**, **immediately halt Path (c)**.
- **Contingency Pivot**: Transition the A100-80GB to a targeted Parameter-Efficient Fine-Tuning (LoRA) run on a curated set of 250 human-corrected responses in Hindi and Kannada only, leaving the other four languages on the stable baseline until native reviewers can be hired.

---

### 6. First Experiment on Day 1
**The "Few-Shot Colloquial Injection" Test**:
1. Hand-craft 3 gold-standard casual conversational pairs in Hindi and Kannada featuring colloquial markers (e.g., Hindi: using *"haan yaar"*, natural postpositions, contracted verbs; Kannada: conversational verb endings like *"-ri"*, *"-pa"* instead of literary *"-uttiddaare"*).
2. Construct a system prompt instructing the model: *"You are a friendly, witty friend talking on WhatsApp. Avoid formal textbook phrasing."*
3. Run inference on FLM-4B across 25 common user queries (15 Hindi, 10 Kannada) on Day 1.
4. Have the reviewer grade the 25 outputs in the first 1-hour session on Day 1 to establish baseline capability.
